# 求职内容总结：按完整招聘流程分类

[资料总览](../README.md) · [原帖索引](../original/index.md)

## 一张图看完整流程

> 市场与岗位定位 → 简历 → 投递与内推 → Recruiter 筛选 → Coding → System Design → BQ / Hiring Manager → 反问与面后跟进 → Offer 决策与谈薪

这组帖子用于判断求职漏斗卡在哪一步，并针对该环节修复。

| 漏斗现象 | 优先排查 |
| --- | --- |
| 大量投递，Recruiter 联系量低 | 岗位定位、简历主线、关键词和项目影响力 |
| Recruiter Call 通过，技术轮转化率低 | 背景与 JD 的匹配度、自我介绍、核心经历表达 |
| Coding 经常挂 | 高频题型、最优解、边界条件、测试与复杂度 |
| System Design 经常挂 | 需求澄清、容量估算、瓶颈、边界场景和取舍 |
| HM / BQ 经常挂 | 案例层级、回答是否切题、影响力、冲突与复盘 |
| 终面后迟迟没有结果 | Thank You Letter、补充信息、候选人排序和 HC 变化 |
| 已获 Offer，条件欠佳 | 风险控制、时间安排、市场数据和谈薪策略 |

## 1. 市场判断与目标岗位定位

这一阶段要回答三个问题：市场正在招什么、自己最强的能力是什么、两者在哪里重合。

- 从至少 20 个当前 JD 中提取反复出现的技能、职责和关键词，依据当前需求判断市场。
- 优先使用可迁移的强项。转方向前先判断现有经验中哪些能力可以迁移。
- 转岗时优先研究内部机会；通过 Mentor、目标团队成员和小项目了解真实工作，再决定是否直接外跳。
- AI 时代的工程岗位越来越看重 AI 工具使用、AI 功能开发、工作流、评估和产品取舍。所有候选人都需要证明自己能在 AI 环境中交付。
- Junior 或转行候选人可以在尚未完全匹配时投递，同时说明已有能力如何迁移到正在形成的新岗位。
- 跨国求职需要翻译经历，并调整对协作、Owner 意识、沟通和业务影响的表达方式。

## 2. 简历：先让正确的人愿意面你

简历阶段的目标：让筛选者快速确认候选人与岗位匹配，并看到足够的进入下一轮证据。

### 内容结构

- 先确定一个清晰的目标岗位，把最匹配、最强的经历放在前面。
- 项目描述同时回答：问题有多复杂、个人做了什么、为什么这样决策、结果如何、影响有多大。
- 用可信数字说明规模和结果，并为每个数字提供可解释的依据。
- 大公司通常更重视技术深度、复杂决策和跨团队影响；创业公司还会看技术广度与从 0 到 1 的落地能力。
- 多数有正式工作经验的候选人，应把 GitHub 排在简历、岗位匹配和面试准备之后。
- 有效内容足够时，简历可以写到一页半至两页。删除冗余，保持清晰主线，突出个人贡献。

### 用数据验证简历

- 第一轮先对同一目标方向做范围更广的投递，验证简历是否能产生面试，并保留最想去的岗位。
- 分别记录大、中、小公司投递量和转化率。
- 各规模公司均无回复：大幅调整简历或目标定位。
- 小公司有回复、大公司无回复：检查项目深度、技术栈、职级证据和复杂度表达。
- 简历开始稳定产生面试后，再增加精投和重点公司的比例。

## 3. 投递、内推与主动触达

简历准备好后，重点是把它送到真正相关的人手里。

- 海投用于建立数据样本；目标明确的投递用于争取重点机会。
- 优先顺序可以是：熟人强内推 → 与岗位匹配的 Hiring Manager 直接触达 → 普通内推 → 官方渠道投递。
- 直接联系 HM 时，应同时提供目标岗位、最相关的经历、能解决的问题和简历。
- 出现裁员风险后立即整理简历，同时联系内部团队、过去的同事和外部网络。
- 建立投递表，至少记录岗位、公司规模、来源、投递日期、当前阶段和失败原因。

相关原帖：[裁员后的快速准备](../original/2025-10-31-69050756.md)、[简历与投递 FAQ](../original/2026-07-01-6a459543.md)。

## 4. Recruiter 筛选与整场面试规划

Recruiter 阶段既是筛选，也是获取情报的机会。

- 准备简洁的自我介绍：当前定位、最强证据、为什么匹配这个岗位、为什么现在看机会。
- 主动询问面试结构、每轮重点、公司 Core Values、目标职级和时间安排。
- 面试前三天集中确认重点，按轮次分配复习时间。
- 如果知道面试官姓名，可以研究其职位、级别、团队和项目，以判断对方更偏技术、产品还是管理。
- 对目标公司和产品做真实研究，让后续“Why us”回答超越官网口号。

相关原帖：[面试前三天的准备](../original/2025-07-30-688ab0db.md)、[完整求职复盘](../original/2025-08-08-689588e9.md)。

## 5. Coding 面试

Coding 阶段强调稳定、完整和可复现。

- 熟练掌握高频题型和大约前 200 道常见题。
- 常见 Medium 题要练到掌握变体和底层模式。
- 回答必须包含思路、最优解、全部关键边界条件、测试用例、时间复杂度和空间复杂度。
- 以规定时间内稳定写完并跑通作为练习目标。
- 如果总是在同一类题失败，应按模式归类，专门补底层算法理解。

相关原帖：[Coding/刷题方法](../original/2025-03-04-67c68541.md)。

## 6. System Design 面试

System Design 的核心是用有限时间展现结构化判断和职级相符的技术深度。

### 推荐节奏

1. 快速确认 Functional Requirements。
2. 明确 Non-functional Requirements、用户规模、吞吐量、延迟和可用性。
3. 给出主架构和数据流。
4. 尽早指出可能的 Bottleneck 与 Failure Mode。
5. 把主要时间留给 Deep Dive、Edge Cases 和 Trade-offs。

### 常见问题

- 等面试官逐条告诉自己需求，没有主动定义系统边界。
- 在通用架构上花四十多分钟，导致没有时间深入讨论。
- 把 NFR 和 Bottleneck 当成同一件事。
- 只会背一个标准架构，无法解释容量、失败场景和取舍。
- Senior 目标需要复杂项目经验和判断依据，缺少这些证据会拉低评价。

练习时可以对多道题分别只写需求、容量、瓶颈和边界场景，再与参考方案比较，找出反复出现的思维盲区。

相关原帖：[System Design 基础问题](../original/2025-03-06-67c8e973.md)、[NFR 与 Bottleneck](../original/2025-03-08-67cc58ab.md)。

## 7. BQ 与 Hiring Manager 面试

这一环节容易让背景优秀的候选人拿不到 offer 或被降级。

### 建立故事库

- 准备 10—20 个可以灵活组合的 STAR 故事，覆盖冲突、Owner 意识、客户、交付、失败、学习、压力和跨团队合作。
- 用要点和逻辑记忆故事，根据追问展开不同细节。
- 每个故事都应说明自己的判断与贡献，控制“我们”的使用，并明确个人作用。
- 案例规模必须符合目标职级。Senior 以上候选人需要展示更大的范围、更多利益相关方、更复杂的不确定性和更强的影响力。

### 先理解题目真正考什么

- “与别人意见不一致”通常考察冲突处理和推动能力。
- “失败或不顺利的项目”通常考察责任、复盘和成长。
- “Dive Deep”需要展示层层排查、验证假设和形成结论的过程。
- “Why this company”要结合真实产品体验、岗位能力匹配、未来贡献和文化认同。
- 同一个冲突问题由 PM、工程师或 HM 提出时，关注点不同，回答应随角色调整。

### 用录音或模拟暴露问题

在公司规定和当地法律允许的前提下，复盘录音或 Mock Interview 可以发现：

- 没听完整就开始回答；
- 回答偏离原问题；
- 细节不足或无法应对 Follow-up；
- 案例层级低于目标职级；
- 合作、客户或结果导向的证据不足。

## 8. 面试反问与结束动作

面试最后几分钟用于展示思考并收集决策信息。

推荐询问：

- 团队和 Org 的结构、主要职责及合作方式；
- 岗位是 New Headcount 还是 Backfill；
- HM 对入职者的核心期待；
- 面试官为什么选择继续留在这家公司；
- 团队当前最重要的问题和成功标准。

准备至少一个反问。直接问“我今天面得怎么样”通常只能得到官方回答。

相关原帖：[面试最后五分钟问什么](../original/2025-10-20-68f5b544.md)。

## 9. 面后跟进与等待结果

- Thank You Letter 应补充与决策有关的信息。单纯致谢的信息量有限。
- 如果能联系面试官，可针对面试中未充分展开的能力提供简短证据；没有邮箱时，可以请 Recruiter 转发。
- 作者建议在大约一周内发送，拖得过久后作用会下降。
- 终面后没有消息可能来自能力评价、HC、职级、候选人比较或内部审批变化。
- 被降级或口头表示会发 offer 后失联，应继续跟进，同时保持其他流程并持续投递。

## 10. Offer 选择与谈薪

### 多个流程并行

- 手里已有 offer、理想公司仍在面试时，先判断接受期限、入职时间和失去保底机会的风险。
- 可以尝试把入职时间谈晚，为其他流程留出时间。
- 作者提出过“先接受、之后再反悔”的策略。该做法涉及合同、职业道德、移民身份和声誉风险，需要个案评估。

### 谈薪准备

- 谈之前调查公司薪酬区间、目标职级、候选人市场和 Recruiter 的背景。
- 掌握信息后再报数，避免先给出偏低数字。
- 提前写出对常见问题和施压方式的回答，避免临场被带节奏。
- 没有 Competing Offer 时，可以围绕市场数据、职级、经验和岗位价值争取。
- 最终同时比较总包、现金、股票、奖金、归属周期、职位范围和稳定性。

## 11. 贯穿全流程的复盘机制

把所有环节合起来，最值得复用的是这一套诊断循环：

1. 记录每个机会停在哪一环。
2. 把失败按简历、Coding、System Design、BQ/HM、流程变化分类。
3. 每次只优先修复最早、最频繁的断点。
4. 用新的投递或面试验证修改是否有效。
5. 保留有效做法，继续处理下一个瓶颈。

丈夫长期投入很多时间，活动与漏斗断点错位。简历未通过时继续刷题无法增加面试；HM/BQ 经常失败时继续加投会消耗机会。每一轮投入都应对准当前漏斗中的具体断点。

- 结果和经历均来自账号自述，未进行独立验证。

- 健康问题披露、录音、接受后反悔等做法涉及当地法律、公司政策、移民身份、职业道德和声誉风险，应结合个人情况判断。
